TWO RAILS

Reliability first, creativity when the grammar runs out.

Common requests compile through a validated spec into a hand-written renderer — no generated code in the path. Anything the grammar can't express falls to a code rail inside a sandbox, and the reason is recorded as telemetry that grows the grammar.

Deterministic rail zero generated code

Validated ChartSpec → renderer adapter. Bit-stable across runs; ECharts, Plotly and Matplotlib out of the box, and a public protocol for the rest.

bar line area scatter pie · donut heatmap histogram boxplot
Custom code rail sandboxed, reason recorded

The agent writes make_chart(data) in any library it likes and runs it under bubblewrap, Docker or a microVM. Data enters as a parameter, so refresh still costs nothing.

One review gate for both lints → VLM → interactivity

Deterministic lints run first and cheaply — axis labels, legend, overlap, colorblind-safe palette, and a data-truthfulness re-execution. Only survivors reach the critique model.

GENERATE ONCE

Refresh forever, at zero inference cost.

A chart is a saved spec, not a one-off image. Re-rendering replays the stored transform, so a dashboard of any size refreshes on a cron with no model call and sub-second latency. A drifted schema fails loud with a typed error instead of drawing something quietly wrong.

Overnight, someone renamed a column.

Refresh checks the new snapshot against the fields the spec actually references before rendering anything. The failure mode is a typed error naming the drift — not a chart that looks fine and isn't. Additive drift is ignored, so a harmless migration never trips it.
